## 3. Tool Selection Rationale

| Tool | Reason for Selection |
|---|---|
| Maven | Standard Java build tool, dependency management, Surefire TestNG execution, command-line suite control |
| Selenium WebDriver | Best fit for browser-based functional UI automation |
| TestNG | Supports priorities, groups, XML suites, data providers, setup/teardown, and reporting integration |
| Apache POI | Enables Excel-based test data for business-readable data-driven testing |
| Log4j 2 | Provides detailed execution logs for debugging and audit trail |
| Extent Reports | Generates readable HTML reports with steps, status, screenshots, and system information |
| WebDriverManager | Simplifies browser driver setup |
| Page Object Model | Separates page locators/actions from test logic for maintainability |

## 14. Risk-Based Test Prioritization

| Priority | Meaning | Examples |
|---|---|---|
| Critical | Directly impacts revenue/order placement | Login, product selection, add to cart, checkout, confirmation |
| High | Important validation around the critical path | Product display, billing validation, shipping, payment |
| Medium | Useful regression but not always release-blocking | Cart update, remove item, empty search, multiple products |
| Low | Optional or lower-impact UI behavior | Optional DOB fields and secondary visual checks |

Risk-based execution order:

1. Run the critical suite first for fast business confidence.
2. Run the user-story suite for UI, edge, and performance coverage.
3. Run the full regression suite before release.
4. Use parallel execution only after the suite is stable.
